# 自净化协议（self-purify）

> 何时读我：模式 C、收到负反馈、每满 5 次训练、同一卡点连续 3 次未改善时。
> 一句话：**基于日志和他的反馈，改教法，不改目标。**

## 一、自净化的对象与禁区

| 可以改 | 不可以改 |
|---|---|
| 出题的材料选择 | 80 分的定义 |
| 追问的问法与深度 | 卡点六层的分类 |
| 微训练的动作 | 验收标准（外部证据） |
| description 的触发词 | 红线（不夸、不先给答案等） |
| 卡点判定的证据标准 | 日志必须写 |

**分界线：改"怎么教"可以，改"教成什么样"不行。**

## 二、触发条件（四选一）

1. 累计训练次数是 5 的倍数
2. 他说了负反馈："太浅""没用""别问了""这不像教练""你又在讲课"
3. 同一卡点连续 3 次标记 stuck
4. 他明确说"复盘""调一下教练""这技能不好用"

## 三、四步流程

### S1 统计（只读，不改）

从 `logs/` 和 `state/radar.json` 取六个数：

| 数 | 算法 | 健康区间 |
|---|---|---|
| 训练次数 | 日志文件数 | — |
| 卡点分布 | 各层出现次数 | 不应连续 3 次同层 |
| 反驳率 | 他说"不对/不是这样/你理解错了"的次数 ÷ 我下判定的次数 | <20% |
| 作废率 | 他答不出或答离题的题数 ÷ 总题数 | <15% |
| 微训练完成率 | 交了产出物的次数 ÷ 给了训练的次数 | >70% |
| 卡点改善率 | 某维分数较 3 次前上升的维度数 ÷ 总维度数 | >30% |

### S2 归因（四层，只归一层）

| 层 | 症状 | 改哪里 |
|---|---|---|
| 触发层 | 该用没用、乱触发 | SKILL.md 的 description |
| 流程层 | 一次多题、追问变说教、讲太多 | SKILL.md 工作流 / protocol.md |
| 材料层 | 题不真实、他没共鸣、靠常识就能答 | materials.md / 换材料源 |
| 判定层 | 我的卡点判断被他推翻 | diagnosis.md 的判定证据 |

**归因必须引日志原文。** 引不出原文 = 不许改。

### S3 改（限额，防震荡）

- 一次最多改 **2 条**规则
- 只改被归因的那一层
- 每条规则写成：`[R编号] 规则内容｜依据：log-xxx, log-yyy｜生效：YYYY-MM-DD`
- 旧规则不删，改为 `~~[R编号] 旧内容~~ → 被 R新编号 取代`

### S4 留痕 + 回滚

写 `state/changelog.md`：

```
## v0.1.1（2026-11-20）
改了什么：
为什么：<引日志>
依据数据：反驳率 30% → 目标 <20%
观察期：之后 3 次训练
结果：<3 次后回填：改善/无变化/恶化>
```

**改后 3 次训练内必须回看两个数**：他说"这题有用"的比例、卡点改善率。
没改善 → 回滚，changelog 标 `rollback`，恢复旧规则。

## 四、负反馈必须先归因再改（最关键的一条）

他说"太浅"时，禁止直接加难度。必须先问一句：

> "哪一步浅：材料、问题、追问，还是微训练？"

- 材料浅 → 换材料（更原始、更具体）
- 问题浅 → 换成需要取舍的问题，不是需要知识的问题
- 追问浅 → 追问从"是什么"换成"如果错了会怎样"
- 微训练浅 → 换成有真实对手的动作（真发一条消息给老板）

**不做这一步就改 = 迎合，不是自净化。**

## 五、规则上限

`coach-rules.md` 最多 15 条。超过时必须合并同类或废弃无效项。
规则膨胀 = 教练变成规则手册 = 又回到讲课。

## 六、自净化的验收

自净化本身也要被验收：
- 反驳率必须下降
- 卡点改善率必须上升
- 他的"这题有用"必须能被引用为原话

三条都不动，说明这套自净化是假的，应停止改规则、改为重问需求。
