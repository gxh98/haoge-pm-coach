# 昊哥-产品经理教练（haoge-pm-coach）

> 不讲课，只出题、只追问。用你自己的真实材料，一次练一个判断，练完留痕，并按你的反馈调整教法。

## 为什么有它

产品经理的能力不是知识，是判断。知识可以听，判断只能练。

而「练」需要四样东西，市面上的教练类提示词四样全缺：

| 练判断需要 | 大多数教练提示词的做法 |
|---|---|
| 真实的一手材料 | 用编的例子、行业报告的结论 |
| 一次只练一个 | 一次甩十个问题、一整套框架 |
| 有人指出你卡在哪 | 直接给你「更好的答案」 |
| 练完留痕、事后对账 | 聊完就散，下次从零开始 |

这个技能把这四样做成流程，并且加了第五样：**它会根据你的反馈改自己的教法**。

## 80 分的定义（唯一验收口径，锁死不许改）

> 在信息不全、时间不够、资源不足时，能独立完成：定义真问题 → 给出可被推翻的假设 → 做出取舍并说清放弃什么 → 用最小成本验证 → 用真实结果修正判断。

不考核术语、原型工具、文档格式、方法论背诵。

## 六维能力

用户洞察 · 问题定义 · 方案取舍 · 优先级 · 度量 · 推动与决策

每维有 0-40 / 60 / 80 / 95 四档**行为锚点**（见 `references/diagnosis.md`），打分只依据实际表现，不依据自我评价。

## 三种模式

| 模式 | 触发 | 动作 |
|---|---|---|
| A 基线测 | 首次使用 /「测测我」 | 6 题盲测覆盖六维，输出雷达 |
| B 单题训练 | 默认 /「练一题」 | 一轮一题，七步走完 |
| C 自净化复盘 |「复盘」/「调一下」/ 每满 5 次 | 读日志 → 归因 → 改规则 → 版本进位 |

每轮 B 模式的完整链路：

出题（材料＋一个问题）→ 你答（判断／依据／置信度）→ 我只追问（最多 3 轮，只问句）→ 卡点定位（六层指一层，引你原话）→ 微训练（一个动作，5-30 分钟，有产出）→ 写日志 → 说下次练什么

## 自净化：它凭什么「越用越准」

不是「根据反馈微调」这种话，是五件套：

| 件 | 做法 |
|---|---|
| 数据源 | 每次训练原样记录你的作答与反馈，雷达记分数与计数，规则带编号与依据 |
| 触发 | 每满 5 次 / 你给负反馈 / 同一卡点连续 3 次未改善 / 你说「复盘」 |
| 归因 | 四层：触发层、流程层、材料层、判定层。**必须引日志原文，引不出不许改** |
| 变更 | 一次最多改 2 条，只改被归因那层，旧规则标废弃不删，版本 +0.1 |
| 回滚 | 改后 3 次回看两个数：你说「这题有用」的比例、卡点改善率。没升就回滚 |

三条防跑偏——这是「自净化」和「迎合」的分界线：

1. 只能改教法，不能改 80 分定义与验收标准
2. 你说「太浅」，它必须先问「哪一步浅：材料、问题、追问、还是微训练」。直接加难度是迎合
3. 规则上限 15 条，超了必须合并。规则膨胀等于又回到讲课

## 目录结构

```
haoge-pm-coach/
├── SKILL.md                       # 三模式 + 9 步工作流 + 红线表
├── references/
│   ├── protocol.md                # 追问话术库（按六层分类）+ 输出格式
│   ├── diagnosis.md               # 六维行为锚点 + 卡点六层判定 + 打分规则
│   ├── materials.md               # 一手材料分级 + 禁用清单 + 材料不足即停
│   ├── drills.md                  # 微训练库（六层 × 4 个动作）
│   └── self-purify.md             # 自净化协议（触发/统计/归因/改/回滚）
└── assets/
    ├── session-log-template.md    # 训练日志模板
    ├── radar.json                 # 六维雷达模板
    ├── coach-rules.md             # 教法规则（锁死 2 条 + 可演化 6 条）
    └── changelog.md               # 变更记录模板
```

**运行时目录外置。** 日志和状态写在工作目录的 `state/` 与 `logs/`，不写进技能目录——技能目录通常只读，写进去会静默失败，自净化就成了摆设。首次使用先建好这两个目录，或从 `assets/` 拷模板。

## 安装

**扣子（Coze）**
已发布到「我的技能」，在 Agent 技能配置里勾选「昊哥-产品经理教练」。

**dsh（DeepSeek Harness）**
把本目录整体放入 dsh 的 skills 目录。

**Claude Code**

```bash
git clone https://github.com/gxh98/haoge-pm-coach ~/.claude/skills/haoge-pm-coach
```

**无文件系统的环境**
日志正文直接输出到对话里，你自己存；状态改为对话内累积，每次开头复述。

## 使用方式

对模型说：

- 「练一题」
- 「测测我的产品判断」
- 「这题太浅」
- 「复盘我的训练」

它会接管后续流程。**不要问它「产品经理该怎么练」**——那会触发讲课，不是这个技能的用法。

## 设计来源

- 建造工艺：昊哥-技能熔炉（skill-forge）场景 B
- 方法论参照：case interview（出题—追问—判定）、The Mom Test（只问过去不问未来）、JTBD、pre-mortem、判断日志法
- 核心取舍：**深度优先于广度**——宁可一个维度练十轮，不做一套课程表
